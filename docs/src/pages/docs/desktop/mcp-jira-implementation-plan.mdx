# JIRA MCP Server - Comprehensive Implementation Plan

This document outlines a complete development plan for integrating JIRA as a Model Context Protocol (MCP) server within Jan. This plan is designed to be scalable and reusable for future MCP server integrations.

## Executive Summary

**Goal**: Enable Jan users to interact with JIRA projects, issues, and workflows through natural language conversation.

**Scope**: Full JIRA integration supporting issue management, project navigation, workflow operations, and team collaboration.

**Timeline Estimate**: 4-6 weeks for full implementation

**Complexity**: Medium-High (requires external API integration, authentication handling, and comprehensive tool definitions)

## 1. Architecture Overview

### 1.1 MCP Server Architecture in Jan

Jan's MCP implementation follows a three-layer architecture:

```
┌─────────────────────────────────────────────────────────────┐
│                    Frontend Layer (TypeScript)               │
│  - React UI components for MCP server management            │
│  - Tool selection and permission dialogs                    │
│  - MCP server configuration forms                           │
│  - Tool call visualization                                   │
└─────────────────────────┬───────────────────────────────────┘
                          │ Tauri IPC
┌─────────────────────────▼───────────────────────────────────┐
│                   Backend Layer (Rust)                       │
│  - MCP server lifecycle management (start/stop/restart)     │
│  - Transport layer (stdio, HTTP, SSE)                       │
│  - Tool discovery and routing                               │
│  - Error handling and retry logic                           │
│  - Configuration persistence (mcp_config.json)              │
└─────────────────────────┬───────────────────────────────────┘
                          │ Process/Network
┌─────────────────────────▼───────────────────────────────────┐
│              External MCP Server (Node.js/Python)            │
│  - JIRA API client                                          │
│  - Tool implementations                                      │
│  - MCP protocol compliance                                   │
│  - Authentication handling                                   │
└─────────────────────────────────────────────────────────────┘
```

## 2. JIRA MCP Server Specification

### 2.1 Core Features

#### Issue Management Tools
- `jira_create_issue` - Create new issues with all standard fields
- `jira_get_issue` - Retrieve issue details by key or ID
- `jira_update_issue` - Modify existing issues
- `jira_delete_issue` - Delete issues (with confirmation)
- `jira_search_issues` - JQL-based issue search
- `jira_assign_issue` - Assign issues to users
- `jira_transition_issue` - Move issues through workflow states
- `jira_link_issues` - Create relationships between issues
- `jira_add_comment` - Add comments to issues
- `jira_get_comments` - Retrieve issue comments
- `jira_add_attachment` - Upload files to issues
- `jira_get_attachments` - List and download attachments

#### Project & Workflow Tools
- `jira_list_projects` - Get all accessible projects
- `jira_get_project` - Retrieve project details
- `jira_list_issue_types` - Get available issue types for a project
- `jira_list_priorities` - Get priority levels
- `jira_list_statuses` - Get workflow statuses
- `jira_get_transitions` - Get available transitions for an issue
- `jira_list_components` - Get project components

#### Team & User Tools
- `jira_list_users` - Get project/assignable users
- `jira_get_user` - Get user details
- `jira_search_users` - Search for users

#### Sprint & Board Tools (Agile)
- `jira_list_boards` - Get Scrum/Kanban boards
- `jira_get_board` - Get board details
- `jira_list_sprints` - Get sprints for a board
- `jira_get_sprint` - Get sprint details
- `jira_move_to_sprint` - Add issues to sprint

#### Advanced Features
- `jira_create_filter` - Save JQL search filters

- `jira_bulk_update_issues` - Update multiple issues at once
- `jira_get_changelog` - Get issue history
- `jira_watch_issue` - Subscribe to issue notifications
- `jira_vote_issue` - Vote for an issue

### 2.2 Authentication Strategy

JIRA supports multiple authentication methods:

1. **API Token** (Recommended for Cloud)
   - User-generated token from Atlassian account settings
   - Base64 encoded `email:api_token` in Basic Auth header
   - Secure and revocable

2. **Personal Access Token** (For Data Center/Server)
   - Token-based authentication
   - Bearer token in Authorization header

3. **OAuth 2.0** (Advanced)
   - Three-legged OAuth flow
   - Best for distributed applications
   - Requires callback URL setup

**Recommended Implementation**: Start with API Token (option 1) for simplicity and security.

#### 3.1.2 JIRA API Client Implementation

```typescript
// src/jira-client.ts
import axios, { AxiosInstance } from 'axios';

export interface JiraConfig {
  url: string;
  email: string;
  apiToken: string;
}

export class JiraClient {
  private client: AxiosInstance;
  
  constructor(config: JiraConfig) {
    const auth = Buffer.from(`${config.email}:${config.apiToken}`).toString('base64');
    
    this.client = axios.create({
      baseURL: `${config.url}/rest/api/3`,
      headers: {
        'Authorization': `Basic ${auth}`,
        'Accept': 'application/json',
        'Content-Type': 'application/json',
      },
    });
  }
  
  async createIssue(data: CreateIssueParams): Promise<JiraIssue> {
    const response = await this.client.post('/issue', {
      fields: {
        project: { key: data.project },
        summary: data.summary,
        issuetype: { name: data.issueType },
        description: this.formatDescription(data.description),
        priority: data.priority ? { name: data.priority } : undefined,
        assignee: data.assignee ? { name: data.assignee } : undefined,
      },
    });
    return response.data;
  }
  
  async getIssue(issueKey: string): Promise<JiraIssue> {
    const response = await this.client.get(`/issue/${issueKey}`);
    return response.data;
  }
  
  async searchIssues(jql: string, maxResults = 50): Promise<JiraSearchResult> {
    const response = await this.client.post('/search', {
      jql,
      maxResults,
      fields: ['summary', 'status', 'assignee', 'priority', 'created', 'updated'],
    });
    return response.data;
  }
  
  async updateIssue(issueKey: string, fields: Partial<IssueFields>): Promise<void> {
    await this.client.put(`/issue/${issueKey}`, { fields });
  }
  
  async transitionIssue(issueKey: string, transitionId: string): Promise<void> {
    await this.client.post(`/issue/${issueKey}/transitions`, {
      transition: { id: transitionId },
    });
  }
  
  async addComment(issueKey: string, comment: string): Promise<JiraComment> {
    const response = await this.client.post(`/issue/${issueKey}/comment`, {
      body: this.formatDescription(comment),
    });
    return response.data;
  }
  
  async listProjects(): Promise<JiraProject[]> {
    const response = await this.client.get('/project');
    return response.data;
  }
  
  async getTransitions(issueKey: string): Promise<JiraTransition[]> {
    const response = await this.client.get(`/issue/${issueKey}/transitions`);
    return response.data.transitions;
  }
  
  // JIRA uses Atlassian Document Format (ADF) for rich text
  private formatDescription(text?: string): any {
    if (!text) return undefined;
    
    return {
      type: 'doc',
      version: 1,
      content: [
        {
          type: 'paragraph',
          content: [
            {
              type: 'text',
              text: text,
            },
          ],
        },
      ],
    };
  }
  
  // Add more methods for other endpoints...
}
```

#### 3.1.3 Tool Handlers Implementation

```typescript
// src/handlers/issue-handlers.ts
import { JiraClient } from '../jira-client.js';

export async function handleCreateIssue(args: any, client: JiraClient) {
  try {
    const issue = await client.createIssue({
      project: args.project,
      summary: args.summary,
      issueType: args.issueType,
      description: args.description,
      priority: args.priority,
      assignee: args.assignee,
    });
    
    return {
      content: [
        {
          type: 'text',
          text: `Successfully created issue ${issue.key}: ${args.summary}\n` +
                `URL: ${process.env.JIRA_URL}/browse/${issue.key}`,
        },
      ],
    };
  } catch (error) {
    return {
      content: [
        {
          type: 'text',
          text: `Error creating issue: ${error.message}`,
        },
      ],
      isError: true,
    };
  }
}

export async function handleGetIssue(args: any, client: JiraClient) {
  try {
    const issue = await client.getIssue(args.issueKey);
    
    return {
      content: [
        {
          type: 'text',
          text: formatIssueDetails(issue),
        },
      ],
    };
  } catch (error) {
    return {
      content: [
        {
          type: 'text',
          text: `Error fetching issue: ${error.message}`,
        },
      ],
      isError: true,
    };
  }
}

function formatIssueDetails(issue: any): string {
  return `
Issue: ${issue.key} - ${issue.fields.summary}
Status: ${issue.fields.status.name}
Type: ${issue.fields.issuetype.name}
Priority: ${issue.fields.priority?.name || 'None'}
Assignee: ${issue.fields.assignee?.displayName || 'Unassigned'}
Reporter: ${issue.fields.reporter?.displayName || 'Unknown'}
Created: ${new Date(issue.fields.created).toLocaleDateString()}
Updated: ${new Date(issue.fields.updated).toLocaleDateString()}

Description:
${extractTextFromADF(issue.fields.description)}

URL: ${process.env.JIRA_URL}/browse/${issue.key}
  `.trim();
}

// Helper to extract text from Atlassian Document Format
function extractTextFromADF(adf: any): string {
  if (!adf) return 'No description';
  // Simplified - implement full ADF parser for production
  return JSON.stringify(adf);
}
```

#### 3.1.4 Error Handling & Validation

```typescript
// src/utils/validation.ts
export function validateEnvironment() {
  const required = ['JIRA_URL', 'JIRA_EMAIL', 'JIRA_API_TOKEN'];
  const missing = required.filter(key => !process.env[key]);
  
  if (missing.length > 0) {
    throw new Error(`Missing required environment variables: ${missing.join(', ')}`);
  }
  
  // Validate JIRA URL format
  const url = process.env.JIRA_URL!;
  if (!url.startsWith('http://') && !url.startsWith('https://')) {
    throw new Error('JIRA_URL must start with http:// or https://');
  }
}

export function validateIssueKey(key: string): boolean {
  // JIRA issue key format: PROJECT-123
  return /^[A-Z]+-\d+$/.test(key);
}

export function validateProjectKey(key: string): boolean {
  // JIRA project key: uppercase letters only
  return /^[A-Z]+$/.test(key);
}
```

```rust
pub fn migrate_mcp_servers_v3(
    app_handle: tauri::AppHandle,
    store: Arc<Store<Wry>>,
) -> Result<(), String> {
    let current_version = store.get("mcp_version").and_then(|v| v.as_u64()).unwrap_or(0);
    
    if current_version >= 3 {
        return Ok(());
    }
    
    // Add JIRA MCP server if not present
    let result = add_server_config(
        app_handle,
        "JIRA".to_string(),
        serde_json::json!({
            "command": "npx",
            "args": ["-y", "@janhq/jira-mcp-server"],
            "env": {
                "JIRA_URL": "",
                "JIRA_EMAIL": "",
                "JIRA_API_TOKEN": "",
                "JIRA_DEFAULT_PROJECT": ""
            },
            "active": false,
            "official": true
        }),
    );
    
    if let Err(e) = result {
        log::error!("Failed to add JIRA MCP server config: {e}");
    }
    
    store.set("mcp_version", 3);
    store.save().expect("Failed to save store");
    Ok(())
```

```typescript
    type: { enum: ['stdio', 'http', 'sse'] },
    url: { type: 'string', format: 'uri' },
    timeout: { type: 'number', minimum: 1 },
  },
};

export function validateMCPConfig(config: unknown): boolean {
  const ajv = new Ajv();
```

## 9. Risk Mitigation

### 9.1 Technical Risks

| Risk | Impact | Probability | Mitigation |
|------|--------|-------------|------------|
| JIRA API changes | High | Medium | Version pinning, comprehensive tests |
| Rate limiting | Medium | High | Client-side throttling, caching |
| Auth token expiry | High | Low | Clear error messages, refresh guidance |
| Network failures | Medium | Medium | Retry logic, timeout handling |
| Large response payloads | Low | Medium | Pagination, field filtering |

### 9.2 Security Risks

| Risk | Impact | Probability | Mitigation |
|------|--------|-------------|------------|
| Token leakage | Critical | Low | Secure storage, no logging |
| JQL injection | High | Medium | Input validation, parameterized queries |
| XSS via descriptions | Medium | Low | Content sanitization |
| Unauthorized access | High | Low | Proper permission checks |

### 9.3 User Experience Risks

| Risk | Impact | Probability | Mitigation |
|------|--------|-------------|------------|
| Complex setup | High | High | Step-by-step guide, validation |
| Tool confusion | Medium | Medium | Clear naming, descriptions |
| Overwhelming features | Medium | High | Progressive disclosure, defaults |
| Error messages unclear | Medium | High | User-friendly error formatting |
